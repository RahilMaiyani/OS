Type 1: Contiguous Memory Allocation (First-Fit, Best-Fit, Worst-Fit) Unit 6
Practice Book Question (Q219, Q220, Q228):
Given 5 memory partitions in order: 100K, 500K, 200K, 300K, 600K.
How would First-Fit, Best-Fit, and Worst-Fit place the incoming processes: 212K, 417K, 112K, 426K (in order)? Which algorithm makes the most efficient use of memory?
1. First-Fit Allocation (Allocate the FIRST hole big enough)
Process Partition Chosen Remaining Free Space in Partition Status
P1 (212K) 500K (First hole ≥ 212K; 100K is skipped) 500K - 212K = 288K left Allocated
P2 (417K) 600K (First hole ≥ 417K; 100K, 288K, 200K, 300K skipped) 600K - 417K = 183K left Allocated
P3 (112K) 288K (First hole ≥ 112K; 100K is skipped, next hole is 288K) 288K - 112K = 176K left Allocated
P4 (426K) None! Available holes: 100K, 176K, 200K, 300K, 183K. Largest is 300K. Cannot fit 426K! Must Wait (Fails)
2. Best-Fit Allocation (Allocate the SMALLEST hole big enough)
Process Available Holes Best-Fit Partition Chosen Leftover
P1 (212K) 100K, 500K, 200K, 300K, 600K 300K (Smallest hole ≥ 212K) 300K - 212K = 88K
P2 (417K) 100K, 500K, 200K, 88K, 600K 500K (Smallest hole ≥ 417K) 500K - 417K = 83K
P3 (112K) 100K, 83K, 200K, 88K, 600K 200K (Smallest hole ≥ 112K) 200K - 112K = 88K
P4 (426K) 100K, 83K, 88K, 88K, 600K 600K (Smallest hole ≥ 426K) 600K - 426K = 174K

✔ Best-Fit Result: ALL 4 processes are successfully allocated!

3. Worst-Fit Allocation (Allocate the LARGEST hole available)

P1 (212K) takes 600K (leaving 388K) → P2 (417K) takes 500K (leaving 83K) → P3 (112K) takes 388K (leaving 276K) → P4 (426K) FAILS because largest remaining hole is only 300K.

Exam Conclusion: Best-Fit makes the most efficient use of memory because it successfully places all 4 processes without leaving any process waiting. First-Fit and Worst-Fit both fail to allocate process P4 (426K).
Type 2: Effective Memory Access Time (TLB Hit / Miss Math) Unit 6
Formulas to Memorize:
Case A (TLB search ignored): EMAT = [ α × (t_mem) ] + [ (1 - α) × (t_page_table + t_mem) ]
Case B (TLB search considered): EMAT = t_tlb + [ α × (t_mem) ] + [ (1 - α) × (t_page_table + t_mem) ]
Q223: Ignore TLB Search Time

Hit ratio (α) = 75% = 0.75
Memory reference (t_mem) = 100 ns
Page table access (t_pt) = 100 ns

• TLB Hit (75%): 1 memory access = 100 ns
• TLB Miss (25%): Page table (100) + Memory (100) = 200 ns
Calculation:
EMAT = 0.75 × 100 + 0.25 × 200
EMAT = 75 + 50 = 125 ns
Q224: Ignore TLB Search Time

Hit ratio (α) = 85% = 0.85
Memory reference (t_mem) = 100 ns
Page table access (t_pt) = 50 ns

• TLB Hit (85%): 1 memory access = 100 ns
• TLB Miss (15%): Page table (50) + Memory (100) = 150 ns
Calculation:
EMAT = 0.85 × 100 + 0.15 × 150
EMAT = 85 + 22.5 = 107.5 ns
Q227: With 20ns TLB Search Time

Hit ratio (α) = 75% = 0.75, TLB time = 20 ns
Memory reference = 100 ns, Page table = 100 ns

• TLB Hit (75%): 20 + 100 = 120 ns
• TLB Miss (25%): 20 + 100 + 100 = 220 ns
Calculation:
EMAT = 0.75 × 120 + 0.25 × 220
EMAT = 90 + 55 = 145 ns

Type 4: Disk Scheduling Algorithms (FCFS, SSTF, SCAN, LOOK, C-SCAN, C-LOOK) Unit 8
Practice Book Question (Q303):
Disk drive with 200 cylinders (0 to 199). Currently serving at cylinder 53, and previous request was at 43 (Head is moving towards higher/increasing cylinders).
Pending Request Queue (FIFO): 98, 183, 37, 122, 14, 124, 65, 67.
Calculate Total Head Movement (THM in cylinders) for all scheduling algorithms!
1. FCFS (First-Come, First-Served)
53 → 98 → 183 → 37 → 122 → 14 → 124 → 65 → 67
THM = |98-53| + |183-98| + |37-183| + |122-37| + |14-122| + |124-14| + |65-124| + |67-65|
THM = 45 + 85 + 146 + 85 + 108 + 110 + 59 + 2 = 640 Cylinders
2. SSTF (Shortest Seek Time First) → Always pick the closest pending track

From 53: Closest is 65 (|65-53|=12) → then 67 → 37 (|37-67|=30 vs |98-67|=31) → 14 → 98 → 122 → 124 → 183

53 → 65 → 67 → 37 → 14 → 98 → 122 → 124 → 183
THM = (67 - 53) + (67 - 14) + (183 - 14) = 14 + 53 + 169 = 236 Cylinders
3. SCAN (Elevator Algorithm) → Goes UP to end boundary (199), then reverses
53 → 65 → 67 → 98 → 122 → 124 → 183 → 199 (boundary) → 37 → 14
Shortcut: (199 - 53) + (199 - 14) = 146 + 185 = 331 Cylinders
4. LOOK → Goes UP to last request (183, NOT 199), then reverses
53 → 65 → 67 → 98 → 122 → 124 → 183 → 37 → 14
Shortcut: (183 - 53) + (183 - 14) = 130 + 169 = 299 Cylinders
5. C-SCAN (Circular SCAN) → Goes to 199, jumps to track 0, scans up
53 → ... → 183 → 199 → 0 (jump) → 14 → 37
THM = (199 - 53) + (199 - 0) + (37 - 0) = 146 + 199 + 37 = 382 Cylinders
6. C-LOOK → Goes to last request 183, jumps directly to lowest request 14
53 → ... → 183 → 14 (jump) → 37
THM = (183 - 53) + (183 - 14) + (37 - 14) = 130 + 169 + 23 = 322 Cylinders
Algorithm Total Head Movement (Cylinders) Key Exam Distinguisher
FCFS640Servicing strictly in arrival order (highest overhead)
SSTF236 (Lowest)Closest track next (risk of starvation for far tracks)
SCAN331Touches track 199 before reversing direction
LOOK299Reverses right at track 183 (avoids traveling to 199)
C-SCAN382Touches 199, jumps to 0, uniform wait time
C-LOOK322Reverses at 183, jumps directly to 14 (skips 199 and 0)
Seek Time Calculation (e.g. Q302): If exam says "A seek takes 5 ms per cylinder", then:
Total Seek Time = Total Head Movement (THM) × Time per cylinder → e.g. for SSTF: 236 × 5 ms = 1180 ms = 1.18 sec.

Part 3: High-Yield Short Theory Points Target: 5–8 Marks
Exact Practice Book titles answered in simple, punchy exam-ready bullet points
Internal vs External Fragmentation Unit 6 · Q215
  • Internal Fragmentation: Memory allocated to a process is slightly larger than requested. The unused portion inside the allocated partition is wasted (occurs in fixed partitioning & paging).
  • External Fragmentation: Total free memory exists to satisfy a request, but it is broken into small non-contiguous holes scattered across RAM (occurs in variable partitioning & segmentation).
  • Solution: Compaction solves external fragmentation. Paging completely eliminates external fragmentation by allowing pages to occupy non-contiguous frames.
Swapping in Memory Management Unit 6 · Q204
  • Definition: Temporarily moving an idle or blocked process from main memory (RAM) to a secondary backing store (Hard Disk) to free up RAM.
  • Roll Out / Swap Out: Copying process from RAM to disk.
  • Roll In / Swap In: Reloading process from disk into RAM when CPU is ready to execute it.
  • Significance: Increases degree of multiprogramming and allows total process sizes to exceed physical memory limits.
Paging vs Segmentation Unit 6 · Q236
  • Paging: Non-contiguous scheme dividing memory into fixed-size blocks (Frames in RAM, Pages in process). Invisible to the programmer.
  • Segmentation: Divides program into variable-sized logical units according to programmer's view (functions, stack, data, main).
  • Paging suffers from internal fragmentation; Segmentation suffers from external fragmentation.
  • Paging uses a Page Table (page → frame); Segmentation uses a Segment Table (base & limit).
Demand Paging & Page Fault Handling Unit 7 · Q244/245
  • Demand Paging: Pages are brought into RAM only when demanded (referenced) during execution (Lazy Swapper).
  • Page Fault: Hardware trap triggered when CPU references a page whose valid-invalid bit in the page table is set to invalid (not in RAM).
  • 6-Step Handling: (1) Trap to OS → (2) Save CPU state → (3) Check reference validity → (4) Find free physical frame → (5) Schedule disk I/O to read page → (6) Update page table valid bit & restart instruction.
Thrashing: Causes and Mitigation Unit 7 · Q258/266
  • Definition: A pathological state where the OS spends more time swapping pages in and out than executing actual user instructions.
  • Primary Cause: High degree of multiprogramming. When frames allocated to a process fall below its working set, page faults skyrocket → CPU utilization drops → OS mistakenly admits more processes → system collapses.
  • Mitigation: (1) Working Set Model: Keep entire working set in RAM; (2) Page Fault Frequency (PFF): Suspend processes when page fault rate exceeds upper threshold.
Seek Time, Rotational Latency, & Access Time Unit 8 · Q285-287
  • Seek Time: Time taken by read/write head assembly to travel from current cylinder to target track cylinder.
  • Rotational Latency: Time taken by target disk sector to rotate under the read/write head (avg = 1/2 of full revolution time).
  • Transfer Time: Time required to physically transfer data bits to/from disk surface into memory.
  • Total Access Time: Seek Time + Rotational Latency + Transfer Time.
Direct Memory Access (DMA) Unit 8 · Q296
  • Concept: A dedicated hardware controller that transfers high-speed blocks of data directly between I/O device and main memory without continuous CPU intervention.
  • Working: CPU initiates transfer by supplying starting address and byte count → DMA controller handles the block transfer → interrupts CPU once completed.
  • Benefit: Greatly reduces CPU overhead; CPU remains free to execute other processes concurrently.
Program Threats: Virus vs Worm vs Trojan vs Trapdoor Unit 9 · Q326
  • Virus: Malicious code segment that attaches itself to legitimate host files and reproduces when host runs.
  • Worm: Self-contained, independent program that replicates across computer networks consuming bandwidth/memory.
  • Trojan Horse: Deceptive program appearing completely benign/useful while covertly performing unauthorized malicious acts.
  • Trapdoor (Backdoor): Hidden entry point intentionally left in code to bypass standard authentication controls.
Role of Shell, Kernel, & Unix File System Unit 10 · Q343/344
  • Kernel: Core master software running in privileged mode managing CPU, memory, device I/O, and system calls.
  • Shell: Command-line interpreter acting as interface between user and kernel (reads command → parses → executes).
  • Unix Hierarchical File System: / (root), /bin (essential user binaries: ls, cp), /etc (system config files), /dev (device special files), /home (user home dirs), /var (variable log files).
